# polygon-geometry: non-rectangular rooms in the data model, converter, validators and 2D plot

## Goal
Everything in the backend assumes a rectangle (width x length). Real rooms (L-shaped, bay windows, alcoves, angled walls) are not. Add the room OUTLINE to the contract and carry it through room creation, scan conversion, validation and the 2D plot, exactly as specified in docs/API.md section 1 (bullet "Outline") and section 6 (`POST /rooms/polygon`). A second task (polygon-engine) will then make the optimizer and the acoustics use the outline: do NOT touch backend/app/engine_speakerplacer.py or backend/app/acoustics.py. Also, while in roomplan.py: pick the largest television (by screen area width x height) for the listener's facing instead of the first one in DTO order (ties: first in DTO order); this was a user-resolved design fork.

## Design decisions this brief encodes (do not change)
- Contract exactly as API.md: `outline` optional (`null`/absent = rectangle); `dimensions` = bounding box; one helper `room_outline(room) -> list[[x, z]]` (feet) in backend/app/rooms.py used by every consumer; a pure `point_in_polygon(x, z, outline, margin=0.0)`; polygon validity checker (>= 3 points, simple/no self-intersection, edges >= 0.5 ft, bounding box starts at the origin by shifting) raising a clear `ValueError` for the API's 400.
- `POST /rooms/polygon` per API.md: builds one wall surface per edge (`wall_0..`), floor and ceiling polygons from the outline, default drywall absorption, default listener at the polygon's area centroid (ear height 3.6 ft) facing roughly north and clamped inside, optional `listener`/`facing` validated against the OUTLINE (not the bounding box), `budget`, `session_id` handling same as `/rooms/rect`. Existing `/rooms/rect` and `/rooms/demo` stay byte-for-byte compatible (outline may be null there).
- Validators (`validate_listener` and the converter's clamps) check point-in-polygon against the outline when present; when a requested listener is outside, behave as today for rectangles (clamp/validate the same way: move to the nearest valid interior point and add a warning, or 400 for explicit override, whichever the existing rectangle path does; mirror it).
- Scan conversion (`roomplan.py`): build the outline in the room frame in this order: (1) from the floor surface's `polygon_corners` when it has >= 3 corners (transform with the same yaw/offset logic as walls); (2) else chain the wall segments into a closed loop within 0.5 ft tolerance; (3) else fall back to the wall bounding rectangle and add the warning `scan incomplete; using bounding box`. The frame (`yaw_deg`, `offset`) logic and the section 1a mapping stay as they are and must still round trip (existing tests). `dimensions` = bounding box of the outline. Walls that are not axis-aligned must convert without errors. Keep the no-sofa listener rule (centre of the floor polygon centroid, clamped inside the OUTLINE).
- 2D plot (`web/plot2d/`): draw the room outline from `room.outline` (fallback to the rectangle), clamp dragging to the outline (point-in-polygon), keep rectangles identical. The user also resolved: treatment-patch depth is per-surface plan-view depth (a later task, plot2d-patch-depth, owns that: do not change patch drawing).
- Do not edit the engine adapter, acoustics, products, materials, deploy or docs. The optimizer on a polygon room is the next task; until then do not make `optimize` pretend to support polygons (leave it as is, report in HANDOFF.md what happens).

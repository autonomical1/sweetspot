# engine3d-core: run the new 3D speakerplacer engine and map its output into our layout (no endpoint changes yet)

## Goal
The teammate's new `speakerplacer` engine (merged on master) places a complete home theater in 3D: presets 5.1 / 7.1 / 7.1.4 / ..., real mounting heights, yaw/pitch, speaker box sizes, receiver delay/trim, Dolby/ITU compliance, a screen and projector estimate. Build the foundation that lets the backend use it: a runner that executes the engine headlessly, and a pure mapper from the engine's `schema_version: 2` layout JSON into our layout contract (docs/API.md section 2a, authoritative). Endpoints, the existing adapter, acoustics and the stub are NOT changed in this task: a follow-up task wires it in (staged quick/refined results, because a run takes about 75-95 s).

## Read first
docs/API.md sections 1, 1a, 2, 2a (the new optional fields, role names, units and frame), speakerplacer/ENGINE.md (the engine manual), speakerplacer/cli.py (flags: `--length --width --height --listener --facing --standard --layout --materials --seats --mlp --screen --projector --fast --no-show --no-view3d --save-layout --output --room-polygon-json`), speakerplacer/room_acoustics.py (material preset names), speakerplacer/home_theater.py (`expand_layout`, channel names), backend/app/engine_speakerplacer.py (how the CURRENT adapter converts between our room frame and the engine's world frame: reuse that mapping, do not invent a new one), backend/app/schemas.py (Room/Layout models), fixtures/engine/layout_5.1.json and layout_7.1.4.json (REAL recorded engine outputs for a 15 x 12 x 9 ft room, listener 7.5, 4 facing north: the engine's x runs along `--length`, y along `--width`, z up; front wall (north) is y = width), fixtures/room_rect.json.

## Measured facts (do not re-derive)
Headless `python -m speakerplacer --length 15 --width 12 --height 9 --listener 7.5 4 --facing north --layout 5.1 --standard dolby --fast --no-show --no-view3d --save-layout X.json --output DIR` takes 74 s (5.1) and 94 s (7.1.4) on this machine; the layout JSON is written after about 65 s and the plots after that. Engine channel names in the JSON: 5.1 -> L C R Lss Rss LFE; 7.1.4 -> L C R Lss Rss Lrs Rrs LFE Ltf Rtf Ltr Rtr. Speaker records carry `channel`, `position_ft` [x, y, z] (z up), `aim_direction` (unit vector), `yaw_deg`, `pitch_deg`, `width_m/height_m/depth_m`, `mount_type`, `model_id`, `distance_m`, `receiver_delay_ms`, `receiver_trim_db`, `compliance`. Top-level also has `display` (`screen.geometry`, `projector.position_ft`), `seats`, `standard`, `compliance`, `receiver_calibration`, `room_acoustics`, `first_reflections`, `crossover`, `sub_strategy_comparison`, `warnings`.

## Design decisions this brief encodes (do not change)
- New module `backend/app/engine3d.py`:
  - `build_command(room, listener, *, preset="5.1", standard="dolby", seats=None, output_dir, layout_path, fast=True) -> list[str]`: pure; room dims from `room.dimensions` (bounding box; polygon rooms are out of scope), listener position/facing in the engine's frame, `--materials walls=...,floor=...,ceiling=...` derived from our surface materials (map our drywall/glass/brick/carpet/hardwood/tile/curtain/unknown onto the engine's preset names; unknown or unmapped -> drywall; walls use the most common wall material; floor/ceiling from their surfaces), `--height`, `--layout`, `--standard`, `--fast`, `--no-show`, `--no-view3d`, `--save-layout`, `--output`.
  - `run_scene(room, listener, *, preset, standard, timeout_s=150, workdir=None) -> dict`: runs the CLI with `sys.executable -m speakerplacer` in a subprocess (env `MPLBACKEND=Agg`, cwd repo root), in a temp directory under `$DATA_DIR/tmp` (created, always removed in `finally`), enforces `timeout_s` by killing the whole process tree, returns the parsed JSON (schema_version must be 2), raises `EngineError` (a new exception with the exit code and the last 20 lines of stderr/stdout) on a non-zero exit, missing/invalid JSON or timeout. Never writes into the repo or the current directory.
  - `to_layout(scene: dict, room) -> dict`: pure. Returns `{"layout": {...}, "engine": {...}}` per API.md 2a: speakers with `role` (engine names mapped: 5.1 preset uses `Ls/Rs` for Lss/Rss, 7.x presets keep `Lss Rss Lrs Rrs`; overhead names and `LFE2` pass through), `position` and `aim` as a point (position + aim direction * 1 ft... use position plus 2 ft along `aim_direction`, in the room frame), all in feet and our frame (x width, y up, z length, north = -z) via the SAME transform the current adapter uses (write it once as a small tested helper and reuse it in both directions if practical), plus the optional per-speaker fields (`yaw_deg`, `pitch_deg`, `size` in feet, `mount` normalized, `model_id`, `distance_ft`, `receiver_delay_ms`, `receiver_trim_db`, `compliance` with status and angles), layout-level `preset`, `standard`, `seats`, `projector`, and `screen` built from `display.screen` (wall_id of the front wall, center, width, height in feet); `engine` = the `metrics.engine` payload (compliance rows, receiver_calibration, rt60, first_reflections, crossover, sub_strategy_comparison, warnings).
  - `EngineError`, `PRESETS = ("5.1", "7.1", "5.1.2", "5.1.4", "7.1.2", "7.1.4")` validation with a clear `ValueError` for others.
- Do NOT edit `backend/app/engine_speakerplacer.py`, `engine.py`, `acoustics.py`, `schemas.py`, endpoints, the stub or any teammate file under `speakerplacer/`. If the Layout pydantic model rejects the extra fields, return plain dicts and report it; the follow-up task widens the schema.
- Dependencies: standard library plus what `backend/requirements.txt` already pins. No network.

# products-theater: a complete home theater (receiver, passive speakers, projector-first display, mount, cable)

## Goal
`products.get_products` currently recommends Bluetooth/powered computer speakers and never adds a receiver. Make it return a COMPLETE home-theater setup, exactly as specified in docs/API.md section 4 (bullet "Complete home theater" and the bullets it references: passive-only speakers, bundles, receiver rules, display rule, shares). Also fix the 5 open findings from the products-options reviews, and add a small tool so the orchestrator can grow the catalog (the sandbox has no network and no keys).

docs/API.md section 4 (authoritative; all of it), products/recommend.py, products/value.py, products/variety.py, products/dimensions.py, products/db.py, products/expand.py, backend/tests/products/*.py, products/catalog.py (`classify`, `extract_specs`, `RULES`, `save_listings`, `fetch_with_retry`, `init_db`; teammate file, read-only), products/search.py (read-only), backend/tests/contract/checks.py (`assert_valid_products`, `PRODUCT_ROLES`: you may NOT edit it; if the new roles break it, report in HANDOFF.md and keep the old roles passing; the orchestrator updates it).

## Catalog facts (seed DB, products/av_prices.db)
238 usable speaker listings, only about 99 look passive; standalone centers are rare (7 mention "center", all in bundles such as "R-51M pair + R-52C center") but full "5.1 Home Theater System" packages exist (e.g. Klipsch R-50M 5.1 at about 1,260 USD); 90 receivers (many junk: manuals, covers, "non working"); channel info is in specs `channels` (label like `5.2`) and `channel_count` (sum of digits, so 5.2 -> 7); HDMI cables, mounts and streamers exist; TVs (`display`) are expensive at large diagonals (median about 2,900 USD at 70-89 in) while 90-200 in projection screens have a median of about 700 USD. Only 9 listings mention speaker wire.

## Design decisions this brief encodes (user-approved: "do all" with the recommended defaults; do not change)
- Items in the setup: core (receiver, passive L/R/C/Ls/Rs, powered subwoofer, display) plus mount (projector only) and hdmi_cable; speaker wire only when a decent listing exists; no media streamer.
- Speaker filter: passive only, with a single module-level keyword list (see API.md) in a new `products/theater.py`; apply it to L R C Ls Rs candidates AFTER the usual filters. Subwoofer: powered is fine.
- Display rule: projector + screen by default; a `tv` only if it fits the combined projector + screen share (API.md). TVs are never alternatives of projector items. With a `tv` chosen there are no `screen`/`projector`/`mount` items.
- Bundles: implement as API.md says (`included_in`, first covered role carries the price). Detect bundle coverage from the title with a small, tested function `bundle_roles(title)` in `products/theater.py`: `pair` -> L+R (or Ls+Rs, as today), `with ... center` -> L+R+C, `5.1`/`5.1.x` + `home theater`/`system`/`package` -> L R C Ls Rs LFE (6) or L R C Ls Rs when no subwoofer words; be conservative: an uncertain title covers nothing extra.
- Receiver: rules in API.md; also prefer one whose HDMI/4K specs fit the projector; value = quality - PRICE_PENALTY * price/share as for other roles; quality from rating plus (channels >= needed, hdmi 2.1/8k mention, atmos, wifi) with named constants.
- Shares per API.md; greedy upgrade loop, `2 * share` caps and variety rules from products-spend/products-options stay. The receiver, mount and cable participate in the budget and in the loop like any role.
- Fix the 5 products-options review findings (all valid): (1) after deduplicating alternatives by model, REFILL so the cheaper and pricier choices still appear when eligible candidates exist; (2) front-stage detection must work when the layout has R but no L (and no C), and any single front role; (3) surround variety must differ from the whole front stage L/R/C (not just L/R); (4) alternatives for C and surrounds must use the same contextual candidate filtering (family/variety/passive/bundle rules) as their picks; (5) `variety.model_key` must strip ALL punctuation inside model tokens (`R1280-DB`, `R1280DB`, `R1280 DB` equal; `R-41M` equals `R41M`; `R980T` != `R1280DB`).
- Alternatives (swap options) stay as in API.md for every returned item including receiver/projector/screen/tv-less roles; the TV is not offered as a swap.
- Responses must keep passing `assert_valid_products` for the legacy roles; new roles may need the orchestrator to extend `PRODUCT_ROLES`: report precisely.
- Do not edit the teammate files or the seed database.
